## Source entrypoints and flow

### source/Segment34App.mc — `Segment34App extends Application.AppBase` (`:background`)
- `onStart(state)`: creates `Segment34View`, creates `Segment34Delegate`, calls `scheduleStonksUpdate(isStonksCacheStale())`, returns `[mView, delegate]`.
- `getServiceDelegate()`: returns `[new StonksServiceDelegate()]`.
- `onBackgroundData(data)`: receives cached array from background service; validates `data.size() == StonksData.CACHE_SIZE` (5); preserves P/L from previous cache if new PL is null; stores to `Application.Storage` under `StonksData.CACHE_KEY` ("stonks"); forwards to `mView.onStonksData(data)`; reschedules.
- `onSettingsChanged()`: notifies view, reschedules stonks update (stale = true), requests watch UI update.
- `isStonksCacheStale()`: checks storage cache age vs `stonksTtl` property (minutes).
- `scheduleStonksUpdate(updateNow)`: if no Trading212 credentials, deletes temporal event. If `updateNow`, registers a temporal event 5 min from last run (or now). Otherwise registers/reconfirms interval from `stonksTtl` property (Garmin minimum 5 minutes).
- Market-open check is done inside the background service (`StonksData.isMarketOpen`), not here.

### source/StonksService.mc — `StonksServiceDelegate extends System.ServiceDelegate` (`:background`)
- `onTemporalEvent()`: entry point for background fetches. Reads `t212ClientId`, `t212SecretKey`, `stonksMarket`, cache presence. Exits empty array if no credentials or (cache exists and market closed).
- Calls Trading212 `account/summary` (live/demo base URL from `t212Account` property), then `positions`.
- For each position, maps ticker to Yahoo symbol (`StonksData.yahooSymbol`), aggregates `walletImpact.currentValue` per symbol.
- Fetches Yahoo previous-close prices in batches of 10 (`QUOTES_PER_REQUEST`) from `query1.finance.yahoo.com/v8/finance/spark`.
- `finish(withPl)`: exits `[Time.now().value(), currency, totalValue, dailyPL, dailyPLPercent]`. P/L is null if quote fetch failed (`mPlOk = false`).
- Memory constraint: background process runs in 32–64 KB; portfolios with very many positions may not fit — in that case only portfolio value is updated.

### source/StonksData.mc — shared constants/helpers
- Cache layout (Array, size 5): `[C_TIME=0, C_CURRENCY=1, C_TOTAL=2, C_PL=3, C_PL_PCT=4]`.
- `yahooSymbol(ticker)`: `AAPL_US_EQ` -> `AAPL`; `VODl_EQ` -> `VOD.L`; `SAPd_EQ` -> `SAP.DE`; exchange letters `ldapems` map to `.L .DE .AS .PA .MC .MI .SW`.
- `dailyChange(value, price, prevClose)`: `value * (1 - prevClose/price)`.
- `isMarketOpen(market)`: US 09:30–16:00 NY, EU 09:00–17:30 CET, Mon–Fri, DST-aware. `MARKET_ALWAYS` = always open. No holiday handling.
- `dayOfWeek`, `isUsDst`, `isEuDst` helpers.

### source/StonksFormat.mc — display formatting
- Types: `TYPE_VALUE=79` (portfolio total), `TYPE_PL=80` (daily P/L signed), `TYPE_PL_PCT=81` (daily P/L % unsigned). `NO_DATA = "---"`.
- `getValue(type, width, cache)`:
  - `TYPE_VALUE` → `fit(cache[C_TOTAL], width, signed=false, first=1)`
  - `TYPE_PL` → `fit(cache[C_PL], width, signed=true, first=0)` (returns "---" if PL null)
  - `TYPE_PL_PCT` → `percent(cache[C_PL_PCT], width)`
- `fit(value, width, signed, first)`: tries `scale` at steps `first..DIVIDERS.size()-1`; returns first string whose length ≤ width. `DIVIDERS = [1,1,1000,1000,1e6,1e6]`, `DECIMALS = [1,0,1,0,1,0]`, `SUFFIXES = ["","","K","K","M","M"]`.
- `scale(value, step, signed)`: rounds to 1 decimal if `DECIMALS[step]==1`, strips leading "0." → ".", applies sign (`-` or `+` if signed). Note: the `SUFFIXES` line is commented out — values are NOT suffixed with K/M in current code.
- `percent(value, width)`: unsigned 1-decimal, falls back to integer if too wide; no `%` sign (label shows it).
- `getLabel(type, size, cache)`: localized label strings with optional currency suffix; different label resource for short/medium/long sizes.

Label-width audit tool: `analyze_label_widths.py` parses `storre.fnt` glyph widths and all `strings.xml` `LABEL_*` entries across languages, reports widest labels per category (`_1`, `_2`, `_3`). Run before adding long translated labels.

## Trading212 integration (from README)

Three selectable values for bottom fields:
1. Portfolio value (cash + positions) in account currency
2. Daily P/L in account currency, signed, 1 decimal (e.g. `+123.4`)
3. Daily P/L in percent, unsigned, 1 decimal (e.g. `1.2`; label shows `%`)

Daily P/L = change since previous close of every position (Yahoo Finance prices). Values that don't fit are shortened by /1,000 then /1,000,000.
Settings: Trading212 account (demo/live), API key, API secret (key needs account + portfolio scopes), update interval (cache TTL, 5–60 min), market hours to update in (US/EU/Always).
Background process fetches every TTL minutes only while market is open; result cached forever (never deleted); watch shows latest cached value (`---` until first update).

## Data flow summary

1. `Segment34App.getInitialView()` → creates view + delegate → `scheduleStonksUpdate(isStale?)`.
2. Background `StonksServiceDelegate.onTemporalEvent()` fires every `stonksTtl` minutes (or on-demand +5 min).
3. Service fetches Trading212 summary + positions, maps tickers to Yahoo symbols, fetches previous closes, computes P/L.
4. Service `Background.exit([time, currency, total, pl, plPct])`.
5. Foreground `Segment34App.onBackgroundData()` validates cache, stores to `Application.Storage`, updates view.
6. `Segment34View` renders via `StonksFormat.getValue/getLabel`.
7. `onSettingsChanged()` invalidates cache and requests UI refresh.

## Gotchas for agents

- `manifest.xml` is generated — do not hand-edit products/languages/permissions; use VS Code "Monkey C: Edit Application".
- `monkey.jungle` is the real build config; each device has its own annotation exclusions and resource path — changing shared resources or annotations can silently break specific devices.
- Low-memory devices exclude `WeatherCache`; others exclude `NoWeatherCache`. Code must handle both annotation sets.
- `developer_key` required for signing but is gitignored and absent on fresh clones — builds fail without it.
- `SUFFIXES` in `StonksFormat.scale` is commented out; do not assume K/M suffixes are applied.
- `percent()` has no `%` sign — the label adds it.
- No test suite: verification is manual build + device/simulator deploy.
- Background P/L fetch can fail per-symbol (Yahoo 404 for unknown tickers); those positions count as unchanged; overall `mPlOk` only fails on non-404 errors.
